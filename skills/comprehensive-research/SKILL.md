# 综合研究（Comprehensive Research）

对指定研究对象（商品 / ASIN / 类目 / 店铺 / 账号）做端到端综合研究，产出可执行的经营决策。

## 何时使用

- 用户说「帮我系统分析一下这个品 / 这个店 / 这个类目」
- 需求横跨市场、竞品、关键词、评论、广告、Listing 两个及以上维度
- 需要一份「能不能做、值不值得做、怎么做」的完整结论

## 执行原则

1. **先定对象与边界**：确认研究对象（ASIN / 关键词 / 类目 / 店铺）、站点（默认美国站）、时间范围、目标（选品 / 诊断 / 优化 / 复盘）。
2. **先判信息缺口**：列出每个维度还缺哪些数据，再决定哪些用店铺已有数据、哪些需要外部数据源；不要一上来堆工具。
3. **分维度取证，不编造**：每个结论都必须有数据依据；没有数据就明确说「缺数据」，并给出获取方式。
4. **结论先行**：先给一句话总判断，再给关键数字，最后给行动建议。

## 标准维度与产出

| 维度 | 回答的问题 | 关键指标 |
|---|---|---|
| 市场机会 | 这个市场值不值得进 | 容量、增长率、价格带、集中度 |
| 竞品分析 | 对手是谁、强弱在哪 | 竞品清单、评分/评论数、价格、卖点 |
| 关键词研究 | 用户在搜什么 | 种子词、长尾词、搜索量、竞争度 |
| 评论洞察 | 用户喜欢/抱怨什么 | 好评卖点、差评痛点、改进点 |
| 广告流量 | 流量怎么来、花得值不值 | 流量结构、ACOS、CPC、转化率 |
| Listing | 页面能不能承接流量 | 标题/五点/图片/A+ 完整度与埋词 |

## 数据来源

- **店铺侧（本插件）**：`product_*`（商品）、`stats_*`（销售总览/趋势/TOP/类目）、`order_*`（订单）、`inventory_*`（库存）——用于「自身经营现状」维度。
- **市场侧（外部，按需）**：Amazon 类目/榜单/ABA、第三方选品工具（卖家精灵 / Helium10 / OpenBoost 等）、TikTok Shop 大盘——用于「市场 / 竞品 / 关键词 / 评论 / 广告」维度。

## 输出格式

1. **一句话结论**：能做 / 谨慎 / 不建议 + 核心理由。
2. **关键数据**：表格或要点（标注站点、时间范围、来源）。
3. **机会与风险**：各 2-3 条。
4. **下一步建议**：按优先级 P0/P1/P2 列出可执行动作，并标注由哪个专项技能（market-opportunity / competitor-analysis / keyword-research / review-insight / ad-traffic / listing）深入。
